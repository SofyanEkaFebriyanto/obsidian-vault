# Dev Log — kenfa-2.0 Bottom Navigation Mobile ala Shopee (2026-08-27)

## Context
90% pelanggan kenfa pengguna mobile & terbiasa Shopee. Founder minta adopsi POLA navigasi bawah Shopee (bukan warna — kenfa tetap navy/gold minimal). Keputusan founder: 6 tab (opsi "Pesanan" + tambah Chat CS), sprint ini bottom-nav saja, sisanya masuk plan.

## What changed — bottom nav
1. **`resources/views/partials/mobile-bottom-nav.blade.php` (BARU)**: nav `lg:hidden fixed bottom-0 z-50`, 6 tab urut **Beranda · Kategori · Keranjang · Pesanan · Chat · Akun**.
   - Kategori → `$dispatch('toggle-mobile-menu')` (reuse slide-in menu header, bukan drawer baru).
   - Keranjang → `$store.cart.toggle()` + badge live `$store.cart.count`.
   - Pesanan → guest `route('guest.tracking.form')` (/lacak), login `route('account.orders')` — jaga prinsip guest checkout.
   - Chat → `wa.me` digits-only dari `config('services.whatsapp.number')` + greeting; **auto-hide (jadi 5 tab) kalau nomor kosong** → no link mati.
   - Akun → login `account.index`, guest `login`.
   - Active state gold (`text-accent`) + `aria-current="page"`; deteksi active tanpa `account.*` global biar /akun/pesanan cuma nyalakan tab Pesanan.
   - Safe-area iOS: `pb-[env(safe-area-inset-bottom)]` di nav.
2. **`whatsapp-button.blade.php`**: floating bubble jadi **desktop-only** (`hidden lg:flex`) — Chat sudah jadi tab di mobile, bubble redundan + nutupin konten.
3. **`layouts/app.blade.php`**: `@include` nav + body `pb-[calc(4rem+env(safe-area-inset-bottom))] lg:pb-0`.
4. **Test `tests/Feature/MobileBottomNavTest.php` (BARU)** 7 test / 52 assertion: urutan 6 tab, guest→/lacak, login→/akun/pesanan, /akun/pesanan cuma 1 aria-current, nomor-WA-kosong sembunyikan Chat, digits-only wa.me, WA widget desktop-only.

## Blocker infra yang dibereskan
1. **`localhost:8080` mati (SELinux)**: `docker-compose.yml` bind-mount pakai `:Z` (label private per-container, ganti kategori tiap recreate) → container kehilangan akses `/var/www/html`, `artisan` invisible, `php artisan serve` nunggu selamanya ("Waiting for app source..."). **Fix: `:Z` → `:z`** (shared label) di app/scheduler/queue + relabel `src` ke `container_file_t:s0`. `docker compose up --force-recreate` → server jalan, curl 200. `docker restart` cuma fix sesaat.
2. **SSH deploy timeout (bukan port/kredensial)**: traceroute ke IP SSH `145.79.14.115` mati di hop 7 (`10.192.24.0`, internal ISP) — **ISP null-route IP ini**. Outbound port 22/443/65002 normal (tes ke GitHub OK). Domain resolve ke IP lain (88.223.91.x, di belakang proxy) jadi web tetap 200. **Fix: VPN** — begitu nyala, `ssh hostinger-kenfa` langsung tembus (~270ms). Config SSH sudah benar. → VPN WAJIB nyala tiap deploy.
3. **Test `return-proofs` fail**: `storage/framework/testing/disks/local/return-proofs` root-owned (bekas tulisan container, gejala sama dgn `:Z`). `sudo chown -R sofyan:sofyan storage/framework/testing` → suite hijau.

## Jebakan deploy (.htaccess)
Setelah rsync, **semua route selain `/` → 404 "This Page Does Not Exist"**. Sebab: `public_html/.htaccess` tidak ada di server → front-controller rewrite Laravel hilang, cuma index.php (`/`) yang jalan. **Fix: rsync `public/.htaccess` → `public_html/.htaccess`** → semua 200. WAJIB tiap deploy (masuk MEMO + memory).
